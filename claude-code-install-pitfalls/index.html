CLAUDE CODE, 패키징

claude update가 “최신”이라고 말할 때: Claude Code 설치의 함정 넷

claude update가 “Claude Code is up to date”라고 답했다. 그런데 최신이 아니었다. 거짓말은 아니다 — 자기가 보는 채널에서는 최신이 맞았다. 그 한 줄을 파고들다 채널, 중복 설치, shim 잔재, 그리고 SDK가 몰래 들고 다니는 또 하나의 claude까지 네 개의 함정이 나왔다.

2026-07-25 · 모든 명령 출력은 docker 컨테이너(ubuntu:24.04, node:22, python:3.12 / linux-arm64) 안에서 그날 실제로 실행한 결과다. 호스트에는 아무것도 설치·변경하지 않았다.

이 글에서 실측과 전언의 구분

버전 번호, 채널 이름, 파일 경로, 오류 메시지는 전부 컨테이너에서 재현해 붙였다. 다만 “어느 버전부터 어떤 모델을 쓸 수 있는가”는 계정·구독·로그인 상태에 달려 있어 컨테이너에서 확인할 수 없다. 그 부분은 사례로만 적고 단정하지 않는다. 어디까지가 실측인지는 9절에 따로 정리해 두었다.

1발단: “up to date”인데 최신이 아니다

시작은 평범했다. 새 모델을 쓰려는데 안 돼서 버전을 올리려 했고, 늘 하던 대로 claude update를 실행했다. 답은 “Claude Code is up to date (2.1.212)”. 그런데 그 시점에 세상에 나와 있던 버전은 2.1.219와 2.1.220이었다.

업데이트 명령이 최신이라고 말하는데 최신이 아니다. 버그처럼 보이지만 버그가 아니다. 이 문장에서 생략된 단어가 하나 있다. “(stable 채널에서는) 최신이다.”

여기서부터 조사가 시작됐다. 결론부터 적으면 함정은 네 겹이었고, 서로 독립적이라 하나를 고쳐도 다른 하나가 남는다.

표 1. 이 글에서 다루는 네 가지 함정.

함정증상절
릴리스 채널claude update가 “up to date”인데 더 높은 버전이 존재2–3
중복 설치PATH 순서에 따라 다른 버전의 claude가 실행됨4
shim 잔재No version is set for shim: claude5
SDK 번들 CLI로컬 claude를 올려도 SDK 앱은 옛 버전 그대로7

2채널: 릴리스는 두 줄로 나간다

Claude Code는 같은 버전 번호 체계 위에서 두 개의 채널로 배포된다. latest는 나오는 대로, stable은 한 박자 뒤에서 따라간다. npm의 dist-tag가 그 상태를 그대로 드러낸다.

# docker run --rm node:22 …
$ npm view @anthropic-ai/claude-code dist-tags
{ stable: '2.1.212', latest: '2.1.220', next: '2.1.220' }

npm뿐 아니라 네이티브 빌드를 받아 가는 배포 서버도 채널별 엔드포인트를 따로 둔다. 같은 순간에 두 주소가 서로 다른 번호를 돌려준다.

$ curl -fsSL https://downloads.claude.ai/claude-code-releases/stable
2.1.212
$ curl -fsSL https://downloads.claude.ai/claude-code-releases/latest
2.1.220

얼마나 벌어져 있었나. npm에 찍힌 발행 시각(npm view … time)을 뽑아 보면 stable이 가리키던 2.1.212는 7월 16일 릴리스였고, 그날 latest는 7월 24일에 나온 2.1.220이었다. 여드레, 그 사이 여덟 개 릴리스가 stable 밖에 있었다.

그림 1. 2026-07-25 시점의 두 채널. 점 하나가 npm에 발행된 릴리스 하나이고, 아래 날짜는 npm에 찍힌 발행일이다(간격은 균등 배치). claude update는 자기 채널의 화살표 끝만 본다.

실측: stable에 묶인 설치에서 update를 돌리면

공식 인스톨러는 인자로 채널을 받는다(6절). stable을 주고 설치한 뒤 그대로 claude update를 실행하면, 발단에서 본 그 화면이 그대로 재현된다.

# ubuntu:24.04 컨테이너, 일반 사용자
$ bash install.sh stable
Installing Claude Code native build stable...
✔ Claude Code successfully installed!
  Version: 2.1.212

$ claude update
Current version: 2.1.212
Checking for updates to stable version...
Claude Code is up to date (2.1.212)

메시지를 다시 보면 힌트가 이미 들어 있다. Checking for updates to stable version… — 어느 채널을 보고 있는지 한 줄로 알려 준다. 무심코 지나치기 쉬운 줄이고, 나도 지나쳤다.

claude update는 “세상의 최신”이 아니라 “내 채널의 최신”을 확인한다. stable에 묶여 있으면 latest에 무엇이 올라오든 영원히 up to date다.

3내 설치는 어느 채널인가, 어떻게 바꾸나

확인하는 곳은 claude doctor다. Auto-update channel 줄 하나가 답이다.

$ claude doctor
Claude Code doctor

Running: native (2.1.212)
Commit: 8b2783a8f907
Platform: linux-arm64
Path: /home/<user>/.local/share/claude/versions/2.1.212
Config install method: native
Search: OK (bundled)
Auto-updates: enabled
Auto-update channel: stable

이 값이 저장되는 자리는 ~/.claude/settings.json이고, 키 이름은 autoUpdatesChannel이다. 인스톨러에 stable을 준 직후 파일 내용은 이렇다.

$ cat ~/.claude/settings.json
{
  "autoUpdatesChannel": "stable"
}

그러니 채널을 바꾸는 길은 셋이고, 셋 다 같은 곳을 건드린다. 파일을 직접 고쳐도 되고, 인스톨러를 다시 돌려도 된다. 아래는 파일만 고친 뒤 claude update를 돌린 실측이다. 이번엔 여덟 칸을 건너뛴다.

$ printf '{\n  "autoUpdatesChannel": "latest"\n}\n' > ~/.claude/settings.json

$ claude update
Current version: 2.1.212
Checking for updates to latest version...
Updating to 2.1.220...
Successfully updated from 2.1.212 to version 2.1.220

$ claude --version
2.1.220 (Claude Code)

표 2. 채널을 바꾸는 세 가지 방법(모두 실측).

방법명령결과
인스톨러 인자curl -fsSL https://claude.ai/install.sh | bash -s -- latest해당 채널의 최신을 설치하고 autoUpdatesChannel도 같이 바뀜
설정 파일~/.claude/settings.json의 autoUpdatesChannel 수정다음 claude update부터 새 채널을 봄
버전 직접 지정… install.sh | bash -s -- 2.1.212그 버전으로 고정(롤백에 사용)

주의할 점 하나. 오늘 새로 설치하면 기본값이 무엇인지 확인해 두는 게 좋다. 인자 없이 install.sh를 돌린 컨테이너에서는 latest가 기본이었다(Installing Claude Code native build latest…, 이후 Auto-update channel: latest). npm 전역 설치에서도 latest였다. 즉 stable에 묶인 설치는 “예전에 그렇게 깔렸거나 누군가 그렇게 지정한” 결과이고, 기본값이 바뀌어도 기존 설치의 설정은 따라 바뀌지 않는다. 오래된 머신일수록 한 번은 claude doctor로 확인할 값이다.

그럼 stable을 쓰면 안 되나

아니다. stable은 이름값을 한다. 여러 사람이 같은 버전을 써야 하는 팀이나 CI라면 채널을 stable로 두거나 버전을 아예 고정하는 편이 낫다. 문제는 채널 선택 자체가 아니라, 내가 어느 채널에 있는지 모른 채 claude update의 “up to date”를 최신의 뜻으로 읽는 것이다.

4두 번째 함정: 한 머신에 claude가 여러 벌

채널을 알아내고 나니 두 번째 문제가 드러났다. 머신에 claude가 한 벌이 아니었다. node를 여러 벌 쓰는 환경(배포판 node + 버전 매니저 node)에서는 npm i -g가 각각 다른 전역 디렉터리에 설치되고, 그 결과 이름이 같은 실행 파일이 PATH 위 여러 곳에 놓인다.

컨테이너에서 그대로 재현했다. 우분투의 apt node(18)와 공식 tarball node(22)를 함께 두고, 각각의 npm으로 서로 다른 버전을 설치했다.

$ which -a node
/opt/node22/bin/node
/usr/bin/node
/bin/node

$ which -a claude
/opt/node22/bin/claude
/usr/local/bin/claude

$ ls -l /opt/node22/bin/claude /usr/local/bin/claude
… /opt/node22/bin/claude  -> ../lib/node_modules/@anthropic-ai/claude-code/bin/claude.exe
… /usr/local/bin/claude   -> ../lib/node_modules/@anthropic-ai/claude-code/bin/claude.exe

심볼릭 링크의 상대 경로가 같다는 점이 이 함정의 성격을 잘 보여 준다. 링크 문자열만 보면 구분이 안 되고, 실제로 어디를 가리키는지는 링크가 놓인 디렉터리에 달려 있다. 그래서 실행되는 버전은 오직 PATH 순서로 결정된다.

$ PATH=/opt/node22/bin:/usr/local/bin:/usr/bin:/bin sh -c 'which claude; claude --version'
/opt/node22/bin/claude
2.1.212 (Claude Code)

$ PATH=/usr/local/bin:/opt/node22/bin:/usr/bin:/bin sh -c 'which claude; claude --version'
/usr/local/bin/claude
2.1.195 (Claude Code)

같은 머신, 같은 명령, 다른 버전. 셸을 어디서 띄웠는지, .bashrc에서 PATH를 어떤 순서로 붙였는지, 에디터가 어떤 환경을 물려줬는지에 따라 결과가 갈린다. “아까는 됐는데 지금은 안 되는” 부류의 버그가 여기서 나온다.

npm ls -g도 한 벌만 본다

점검하려고 npm ls -g를 쳐도 함정은 이어진다. 이 명령은 지금 PATH에서 잡히는 npm의 전역 디렉터리만 본다. 그러니 npm도 경로를 박아 각각 물어봐야 전모가 보인다.

$ /usr/bin/npm ls -g --depth=0
/usr/local/lib
`-- @anthropic-ai/claude-code@2.1.195

$ /opt/node22/bin/npm ls -g --depth=0
/opt/node22/lib
+-- @anthropic-ai/claude-code@2.1.212
+-- corepack@0.31.0
`-- npm@10.9.2

# 전역 디렉터리 자체가 다르다
$ /usr/bin/npm root -g
/usr/local/lib/node_modules
$ /opt/node22/bin/npm root -g
/opt/node22/lib/node_modules

npm 전역과 네이티브 설치가 섞이면 같은 일이 벌어진다. 아래는 네이티브 2.1.220을 깐 위에 npm 전역으로 2.1.195를 얹은 컨테이너다. npm 쪽이 PATH 앞에 있어 옛 버전이 이긴다.

$ which -a claude
~/.npm-global/bin/claude
~/.local/bin/claude

$ claude --version
2.1.195 (Claude Code)       # 네이티브로 2.1.220을 깔아 뒀는데도

$ npm rm -g @anthropic-ai/claude-code
removed 3 packages in 52ms

$ hash -r
$ which -a claude
~/.local/bin/claude
$ claude --version
2.1.220 (Claude Code)

hash -r를 빼먹지 말자. bash는 한 번 찾은 실행 파일 경로를 캐시해서, 파일을 지운 뒤에도 같은 셸에서는 옛 경로를 계속 부른다.

5세 번째 함정: 버전 매니저의 shim 잔재

중복을 정리하려고 npm 전역을 지웠더니 이번엔 이런 오류가 났다.

mise ERROR No version is set for shim: claude

mise(그리고 asdf 계열) 같은 버전 매니저는 PATH에 실제 실행 파일 대신 shim을 놓는다. shim은 전부 매니저 본체를 가리키는 링크이고, 실행 시점에 “지금 쓸 버전”을 골라 진짜 바이너리에 넘긴다.

$ ls -l ~/.local/share/mise/shims/claude
… ~/.local/share/mise/shims/claude -> ~/.local/bin/mise

$ claude --version
2.1.212 (Claude Code)

문제는 shim의 수명이 실제 패키지와 따로 논다는 데 있다. 컨테이너에서 경우를 갈라 보니 갈리는 지점이 분명했다.

  • 매니저를 통해 지운 경우는 깨끗했다. mise exec -- npm rm -g @anthropic-ai/claude-code를 돌리면 mise가 Reshimming mise 22…를 스스로 수행하고 claude shim도 함께 사라졌다. mise uninstall node@22.23.1로 런타임을 통째로 지운 경우도 마찬가지였다.
  • 남는 경우는 “패키지는 그대로인데 버전 해석이 끊긴” 때다. node는 설치돼 있는데 설정(~/.config/mise/config.toml)에서 그 도구가 빠지면, shim 파일은 남고 가리킬 버전만 없어진다.
# config.toml에서 node 줄을 뺀 뒤 (shim 파일은 그대로 남아 있다)
$ ls -l ~/.local/share/mise/shims/claude
… ~/.local/share/mise/shims/claude -> ~/.local/bin/mise

$ claude --version
mise ERROR No version is set for shim: claude
Set a global default version with one of the following:
mise use -g node@22.23.1
mise ERROR Version: 2026.7.13 linux-arm64 (2026-07-24)

오류 메시지가 친절해서 오히려 헷갈린다. “node 버전을 정하라”고 안내하지만, 하려던 일은 node를 되살리는 것이 아니라 claude를 네이티브로 옮기는 것이었다. 이 경우 필요한 건 shim 파일을 지우는 것이다.

실측에서 한 가지 더 확인했다. 도구가 하나도 설정되지 않은 상태에서 mise reshim을 돌려도 남아 있던 shim들은 지워지지 않았다(claude corepack node npm npx가 그대로 남았다). reshim은 현재 설치된 도구를 기준으로 shim을 만드는 명령이지 항상 청소해 주는 명령이 아니다. 잔재는 파일을 직접 지우는 게 확실하다.

$ rm ~/.local/share/mise/shims/claude
$ hash -r

6공식 네이티브 인스톨러의 구조

정리의 종착점은 공식 네이티브 인스톨러였다. node에 얹히지 않으니 위의 두 함정(npm 전역 중복, shim)에서 벗어난다.

curl -fsSL https://claude.ai/install.sh | bash

스크립트가 하는 일은 단순하다. 플랫폼(linux-x64, linux-arm64, musl 여부, darwin-*)을 판별해 매니페스트에서 그 플랫폼의 SHA-256을 꺼내고, 바이너리를 받아 체크섬을 대조한 뒤 claude install로 넘긴다. 검증에 실패하면 받은 파일을 지우고 종료한다.

설치 결과의 모양은 이렇다. ~/.local/bin/claude는 실행 파일이 아니라 버전 디렉터리 안의 실제 바이너리를 가리키는 심볼릭 링크다.

$ ls -l ~/.local/bin/claude
lrwxrwxrwx … ~/.local/bin/claude -> ~/.local/share/claude/versions/2.1.220

$ ls -l ~/.local/share/claude/versions/
-rwxr-xr-x … 271825824  2.1.220

버전마다 바이너리가 통째로 한 벌씩 놓이는 구조라, 채널을 옮기거나 롤백하면 파일이 쌓인다. 두 벌이면 500MB를 넘는다. 이 점은 8절의 정리 목록에 넣어 뒀다.

$ bash install.sh 2.1.212      # 특정 버전으로 되돌리기
Installing Claude Code native build 2.1.212...
  Version: 2.1.212

$ ls ~/.local/share/claude/versions/
2.1.212
2.1.220

$ du -sh ~/.local/share/claude/versions/
509M	~/.local/share/claude/versions/

인자로 받는 값은 세 종류뿐이고, 형식이 틀리면 아무것도 하지 않고 거절한다.

$ bash install.sh 2.1
Usage: install.sh [stable|latest|VERSION]
# 종료 코드 1

sudo로 돌리면 거절한다

습관적으로 sudo를 붙이는 사람(나다)을 위한 안전장치도 들어 있다. 설치 경로가 홈 디렉터리라서, sudo로 돌리면 root의 홈에 설치돼 정작 본인 셸에서는 claude를 찾을 수 없게 된다. 스크립트는 그 상황을 먼저 막는다.

$ curl -fsSL https://claude.ai/install.sh | sudo bash
Error: do not run this installer with sudo.

Claude Code installs into your home directory and does not need root access.
With sudo, the installation would go into root's home directory instead of
yours, and the 'claude' command would not work from your own shell.

Please re-run the same command without sudo, e.g.:
    curl -fsSL https://claude.ai/install.sh | bash

조건은 “root이면서 SUDO_USER가 일반 사용자일 때”다. 그래서 컨테이너나 CI처럼 원래부터 root인 환경은 이 검사에 걸리지 않는다. 진짜로 root에 설치하려면 CLAUDE_INSTALL_ALLOW_SUDO=1을 주라고 메시지가 알려 준다.

7네 번째 함정: Agent SDK는 “내” claude를 쓰지 않는다

여기까지가 터미널 이야기다. 그런데 코드에서 Claude를 부르는 경로가 하나 더 있다. Claude Agent SDK(npm @anthropic-ai/claude-agent-sdk, PyPI claude-agent-sdk)다. SDK는 내부적으로 Claude Code CLI를 프로세스로 띄워 쓴다. 그렇다면 로컬 claude를 최신으로 올리면 SDK 앱도 따라 올라갈까?

아니다. SDK는 자기 몫의 CLI를 패키지 안에 넣어 다닌다.

실측 1: 버전이 자물쇠처럼 묶여 있다

SDK의 package.json에 답이 그대로 적혀 있다. claudeCodeVersion 필드와, 플랫폼별 바이너리를 optionalDependencies로 정확한 버전에 고정해 둔 목록이다.

$ npm pack @anthropic-ai/claude-agent-sdk@latest && tar -xzf *.tgz
$ cat package/package.json
{
  "name": "@anthropic-ai/claude-agent-sdk",
  "version": "0.3.220",
  …
  "optionalDependencies": {
    "@anthropic-ai/claude-agent-sdk-linux-x64": "0.3.220",
    "@anthropic-ai/claude-agent-sdk-linux-arm64": "0.3.220",
    "@anthropic-ai/claude-agent-sdk-darwin-arm64": "0.3.220",
    …
  },
  "claudeCodeVersion": "2.1.220"
}

SDK 버전 번호도 우연이 아니다. 0.3.N은 CLI 2.1.N과 짝을 이루고, npm 발행 시각도 초 단위로 붙어 있다. 같은 파이프라인에서 함께 나간다는 뜻이다.

# npm view … time --json 에서 발췌
claude-agent-sdk 0.3.219 : 2026-07-24T16:11:47.390Z
claude-code      2.1.219 : 2026-07-24T16:11:49.832Z   (2초 뒤)
claude-agent-sdk 0.3.220 : 2026-07-24T23:11:19.727Z
claude-code      2.1.220 : 2026-07-24T23:11:21.821Z   (2초 뒤)

실측 2: 설치하면 260MB짜리 claude가 딸려 온다

실제로 설치해 보면 node_modules 안에 CLI 바이너리가 통째로 들어온다. 그리고 SDK 버전을 내리면 딸려 오는 CLI도 같이 내려간다.

$ npm i @anthropic-ai/claude-agent-sdk@0.3.212
$ grep -o '"claudeCodeVersion":[^,}]*' node_modules/@anthropic-ai/claude-agent-sdk/package.json
"claudeCodeVersion": "2.1.212"
$ ./node_modules/@anthropic-ai/claude-agent-sdk-linux-arm64/claude --version
2.1.212 (Claude Code)

$ npm i @anthropic-ai/claude-agent-sdk@latest
$ ./node_modules/@anthropic-ai/claude-agent-sdk-linux-arm64/claude --version
2.1.220 (Claude Code)

$ ls -lh node_modules/@anthropic-ai/claude-agent-sdk-linux-arm64/claude
-rwxr-xr-x … 260M … claude

결정적인 대비는 이것이다. 같은 컨테이너에 시스템 claude를 2.1.195로 깔아 둬도, SDK가 들고 있는 바이너리는 꿈쩍도 하지 않는다.

$ npm i -g @anthropic-ai/claude-code@2.1.195
$ claude --version
2.1.195 (Claude Code)                                  # 시스템 CLI
$ ./node_modules/@anthropic-ai/claude-agent-sdk-linux-arm64/claude --version
2.1.220 (Claude Code)                        # SDK가 쓰는 CLI

실측 3: 파이썬도 같다, 그리고 번들이 PATH를 이긴다

파이썬 SDK도 구조가 같다. 휠 안에 _bundled/claude가 들어 있고(휠 하나가 84MB, 압축을 풀면 260MB), 어느 CLI를 물고 있는지 모듈로 노출한다.

$ pip install claude-agent-sdk
$ cat …/site-packages/claude_agent_sdk/_version.py
__version__ = "0.2.128"
$ cat …/site-packages/claude_agent_sdk/_cli_version.py
__cli_version__ = "2.1.220"
$ …/site-packages/claude_agent_sdk/_bundled/claude --version
2.1.220 (Claude Code)

탐색 순서도 코드에 그대로 적혀 있다. 번들이 먼저고, PATH는 폴백이다.

# claude_agent_sdk/_internal/transport/subprocess_cli.py
    def _find_cli(self) -> str:
        """Find Claude Code CLI binary."""
        # First, check for bundled CLI
        bundled_cli = self._find_bundled_cli()
        if bundled_cli:
            return bundled_cli

        # Fall back to system-wide search
        …
        if cli := shutil.which("claude"):

즉 SDK를 쓰는 앱에서는 which claude가 무엇을 가리키든 상관이 없다. 번들 파일이 존재하는 한 그쪽이 이긴다. 타입스크립트 SDK의 타입 정의도 같은 말을 한다 — pathToClaudeCodeExecutable?: string에 달린 주석이 “Path to the Claude Code executable. Uses the built-in executable if not specified.”다.

그림 2. 두 경로는 서로 다른 것을 실행한다. 터미널은 PATH 순서로 하나를 고르고, SDK 앱은 PATH를 보지 않는다.

그래서 결론

“claude를 올렸는데 SDK 앱만 옛날처럼 군다”는 함정은 실재한다. 조건도 분명하다.

  • SDK 앱이 쓰는 CLI 버전은 설치된 SDK 패키지 버전이 정한다. 로컬 claude를 올려도, 네이티브로 옮겨도, 채널을 바꿔도 바뀌지 않는다.
  • 바꾸려면 SDK를 올려야 한다(npm i @anthropic-ai/claude-agent-sdk@latest / pip install -U claude-agent-sdk). 그리고 lockfile로 버전을 고정해 뒀다면 그것도 같이 풀어야 한다.
  • 굳이 시스템 CLI를 쓰게 하려면 경로를 명시한다. TS는 pathToClaudeCodeExecutable, 파이썬은 ClaudeAgentOptions(cli_path=…)다. 다만 SDK와 CLI는 짝으로 릴리스되므로, 임의 조합은 스스로 검증할 몫이 된다.
  • 지금 뭘 물고 있는지는 한 줄로 확인된다. npm ls @anthropic-ai/claude-agent-sdk 또는 python -c "from claude_agent_sdk._cli_version import __cli_version__ as v; print(v)".

여기서 실측하지 못한 것

“SDK 0.3.212로는 특정 모델 호출이 실패하고 0.3.220으로는 성공한다” 같은 실제 모델 호출 결과는 확인하지 않았다. 인증이 필요해 컨테이너에서 재현할 수 없다. 위에서 확인한 것은 어디까지나 “SDK가 어느 버전의 CLI를 실행하는가”이고, 새 모델 지원이 CLI 버전에 달려 있다면 그 경로로 영향이 간다는 구조다.

8점검·정리 레시피

같은 일을 다시 겪지 않으려면 확인할 것은 결국 두 가지다. “지금 실행되는 게 뭐냐”와 “그게 어느 채널을 보고 있냐”.

자가진단

# 1) 지금 실행되는 claude와, 가려져 있는 나머지
which -a claude
claude --version
claude doctor          # Running / Path / Config install method / Auto-update channel

# 2) 채널 설정이 저장된 자리
cat ~/.claude/settings.json

# 3) npm 전역에 남아 있는 것 — node가 여러 벌이면 npm마다 물어본다
which -a node npm
npm ls -g @anthropic-ai/claude-code
/usr/bin/npm ls -g --depth=0            # 배포판 node 쪽

# 4) 버전 매니저 shim
ls ~/.local/share/mise/shims/ | grep claude

# 5) 네이티브 설치본과 쌓인 버전들
ls -l ~/.local/bin/claude
ls -lh ~/.local/share/claude/versions/

# 6) SDK를 쓰는 프로젝트라면
npm ls @anthropic-ai/claude-agent-sdk
python -c "from claude_agent_sdk._cli_version import __cli_version__ as v; print(v)"

중복 설치 정리

순서가 중요하다. 지우기 전에 무엇이 있는지부터 확인하고, 지운 뒤에는 셸 캐시를 비운다.

# 1) npm 전역을 npm마다 제거 (node가 여러 벌이면 각각)
npm rm -g @anthropic-ai/claude-code
/usr/bin/npm rm -g @anthropic-ai/claude-code

# 2) 버전 매니저 shim 잔재가 남았으면 파일을 직접 제거
rm -f ~/.local/share/mise/shims/claude

# 3) 공식 네이티브 인스톨러로 한 벌만 남긴다 (채널을 명시)
curl -fsSL https://claude.ai/install.sh | bash -s -- latest

# 4) 셸 캐시를 비우고 확인
hash -r
which -a claude && claude --version && claude doctor

# 5) PATH에 ~/.local/bin 이 없으면 추가 (인스톨러도 이 문구로 안내한다)
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc

# 6) 쓰지 않는 옛 버전 바이너리 정리 (한 벌에 약 260MB)
ls -lh ~/.local/share/claude/versions/

6번은 조심할 것. ~/.local/bin/claude가 가리키는 버전은 남겨야 한다. readlink -f ~/.local/bin/claude로 확인한 다음 나머지를 지운다. 롤백용으로 직전 버전 하나쯤 남겨 두면 편하다.

9실측한 것과 그러지 못한 것

이 글의 근거를 분명히 해 둔다.

표 3. 검증 상태.

항목상태
dist-tag/배포 엔드포인트의 stable·latest 값실측 (node:22, 2026-07-25)
stable 설치에서 claude update가 “up to date”실측 (ubuntu:24.04)
autoUpdatesChannel 수정 후 2.1.220으로 갱신실측
PATH 순서로 실행 버전이 갈리는 것실측 (apt node 18 + tarball node 22)
No version is set for shim: claude실측 (mise 2026.7.13)
네이티브 설치 구조·인자·sudo 거부실측
SDK가 CLI를 번들하고 버전이 고정된다는 것실측 (npm·pip 양쪽)
버전별 모델 가용성(opus 5 등)미실측 — 아래 참고

마지막 줄이 이 조사의 출발점이었다는 게 얄궂다. 이번 일의 계기는 “2.1.219부터는 특정 최신 모델을 쓸 수 있고 2.1.212에서는 안 된다”는 전언이었다. 그 말이 조사를 시작하게 했고, 조사 결과 채널이라는 진짜 원인이 나왔다.

하지만 그 전언 자체는 이 글에서 검증하지 못했다. 모델 가용성은 로그인한 계정, 구독 플랜, 조직 설정, 지역 롤아웃에 걸쳐 결정되고, 인증 없는 컨테이너에서는 어느 쪽도 확인할 수 없다. 실제로 컨테이너의 claude doctor는 이렇게 답한다.

Remote Control
Remote Control requires a claude.ai subscription. Run claude auth login …
- Not signed in to claude.ai
- claude.ai subscription auth not active

그러니 이렇게 읽는 게 정확하다. “버전이 올라가면 새 기능·새 모델을 쓸 수 있게 되는 경우가 있다”는 일반적인 사실은 그대로 두고, “정확히 2.1.219부터”라는 경계선은 내 계정에서 관찰된 사례로만 받아들이는 것. 이 글이 실제로 증명한 것은 그 아래 깔린 구조다. 버전이 올라가지 않은 이유가 채널이었다는 것.

10마치며

네 함정에는 공통점이 있다. 전부 “도구가 거짓말을 한 게 아니라, 내가 생략된 주어를 잘못 채운” 경우다.

  • claude update의 “up to date”는 이 채널에서 최신이라는 뜻이었다.
  • claude --version은 PATH에서 처음 걸린 것의 버전이었다.
  • mise의 “No version is set”은 shim은 남았는데 가리킬 곳이 없다는 뜻이었다.
  • SDK가 쓰는 CLI는 내 CLI가 아니라 자기가 들고 온 CLI였다.

도구가 “최신”이라고 말할 때 무엇의 최신인지 되묻는 습관 하나면, 이 네 개는 대체로 claude doctor와 which -a 두 줄에서 끝난다.

부록: 이 문서의 재현 명령 요약 (전부 컨테이너 안에서 실행)

bash install.sh stable && claude update      # -> up to date (2.1.212)
bash install.sh latest && claude --version    # -> 2.1.220

sed -i '/node/d' ~/.config/mise/config.toml
